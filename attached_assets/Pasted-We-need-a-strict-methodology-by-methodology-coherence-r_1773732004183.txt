CORE PROBLEM
==================================================

The application is still inconsistent and currently unsafe in several places.

Examples visible in the UI:

1. Baseline fuel / project fuel is being asked in more than one place, and not always consistently.
   Example: one place shows baseline=wood, project=charcoal, and another place later still shows baseline/project fuel again with different values.

2. SDGs are still being asked too early in the flow.
   This is wrong.
   Some SDGs (especially SDG 13, and partly SDG 1 / SDG 15) depend on later calculations and should be derived after results exist, not asked upfront in setup.

3. Project specific fuel consumption (kg/device/day) and project annual fuel consumption (t/device/year) are still both shown as independent inputs.
   This is duplicate input for the same concept and should be synchronized or reduced to one canonical driver + one derived display.

4. Baseline annual fuel consumption is still mixing incompatible default logics:
   - 0.4 t/person/year × household size
   - 0.5 t/device/year
   These belong to different methodological assumptions and must not be mixed carelessly.

5. Crediting period is still not placed logically in the setup flow.

The app must become methodology-consistent, dependency-aware, and non-duplicative.
